gronka

privacy

short version: gronka keeps no download history and asks for no personal details. this page covers web.gronka.dev and api.gronka.dev. the discord bot has its own policy.

no logs, no history

  • no request logs. gronka doesn't record which links were requested, who asked, or when.
  • no download history or cache. each request starts fresh.
  • no analytics, ads, or trackers. the download page sets no cookies.
  • when something breaks, the server prints an error line for debugging. it strips links, ip addresses, keys and account numbers first. the line goes into a small buffer that overwrites itself.
  • the server keeps a few counters in memory (how many downloads worked, per site). they reset on every restart and hold nothing about you.

your ip address

to stop one person from hogging the server, gronka counts requests per address for 10 minutes. gronka keeps only a keyed hash in memory, not the address itself. the key changes daily, so yesterday's hashes can't be matched.

the files

downloads reach you one of three ways. the page says which:

  • straight from the site. gronka hands your browser the site's own link. gronka never sees the file, but the site sees your ip address, the same as if you had opened it there.
  • streamed through gronka's edge (dl.gronka.dev, a cloudflare worker). the file passes through and is not stored. the site sees cloudflare, not you. these links stop working after an hour.
  • a copy on cdn.gronka.dev. gronka fetches the file, stores it under a random name and deletes it after an hour. the name is random on purpose, so two people downloading the same thing get unrelated links. while it is being prepared the file sits on gronka's server, and that working copy is deleted as soon as the link is ready.

audio-only and trimmed downloads always take the third way, because gronka has to process them.

accounts

you only need one for api keys. an account holds:

  • a hash of your account number (salted argon2id) and of each api key and recovery code (a keyed hash), both mixed with a server secret that is not in the database, never the number or keys themselves;
  • your 2fa secret, if you turned 2fa on, encrypted;
  • the public half of each passkey (the private half never leaves your device);
  • dates: the day things were made, the day each key was last used (so you can spot a leaked key), and the day the account was last used.

an account holds no email, name, ip address, browser details, or download history. while you're logged in, a session cookie keeps you in (stored hashed on our side, gone after a day idle or a week at most). deleting your account removes all of it right away.

unused accounts are deleted on their own: an account never used after the day it was made goes after 90 days, and any other account goes after 365 days without being used. using it means logging in, using the site while logged in, or calling the api with one of its keys.

cloudflare

gronka runs behind cloudflare, so cloudflare sees traffic at its edge like it does for any site it serves. the "are you a person" check on the page is cloudflare turnstile; it loads from cloudflare only once you start using the page. cloudflare's privacy policy covers what they do.

changes

this public preview may change. if gronka changes what it keeps, this page will change first.
