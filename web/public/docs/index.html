gronka openapi.json

api

two calls: get the files behind a link, or read what a link says. json in, json out.

public preview: the api runs at api.gronka.dev and may still change before the release.

start

  1. get a key on the api key page. there are no accounts.
  2. send it on every call as Authorization: Bearer <key>.
  3. post a link as json:
curl https://api.gronka.dev/v1/download \
  -H 'Authorization: Bearer <key>' \
  -H 'Content-Type: application/json' \
  -d '{"url":"https://x.com/user/status/123"}'

download

POST /v1/download

send a link, get the file back as a link you can save.

field what it does
url the link. required.
mode auto (default), audio for an mp3, or mute for the video without its sound.
start, end trim, in seconds or m:ss. end has to be after start.
split false asks for one finished file instead of separate video and audio parts.

a playlist link gives its first 10 videos. a soundcloud set, spotify album or playlist, or apple music album gives up to 25 tracks in one zip. note says when a list was cut short or a track couldn't be found.

where the file is

every answer has a lane and a list of files. the lane says where those links point.

lane the links point to
direct the file on its source site.
worker signed links on dl.gronka.dev, good for an hour. each file has a kind: video, audio or file. with merge: true the files are separate video and audio streams for you to join; send split: false to get one file instead.
r2 a copy on cdn.gronka.dev, deleted after an hour. when gronka had to change the file to deliver it, note says how. 
{
  "lane": "worker",
  "merge": true,
  "filename": "clip.mp4",
  "files": [
    { "url": "https://dl.gronka.dev/f/...", "filename": "clip.video.mp4", "kind": "video", "size": 30123456 },
    { "url": "https://dl.gronka.dev/f/...", "filename": "clip.audio.m4a", "kind": "audio", "size": 1234567 }
  ]
}
{
  "lane": "r2",
  "note": "sent at 720p to fit the 400MB limit.",
  "files": [
    { "url": "https://cdn.gronka.dev/...", "filename": "video.mp4", "type": "video", "size": 312345678 }
  ]
}

long downloads

a download that finishes within about 80 seconds answers with its http status: 200, 400 when the link or options are the problem, 502 when the source failed. a longer one starts sending spaces to keep the connection open, then the json. parse the whole response as usual and check the body for error, since the status is already 200. closing the connection cancels the download.

content

POST /v1/content

the words behind a link, not the file: the post, who wrote it and when, its media, and replies when you ask for them. short links and embed-fixer mirrors are followed first. 

curl https://api.gronka.dev/v1/content \
  -H 'Authorization: Bearer <key>' \
  -H 'Content-Type: application/json' \
  -d '{"url":"https://www.reddit.com/r/pics/comments/abc123/title/","comments":10,"depth":2}'
field works on what it does
url every source the link. required.
format every source json (default) or text: the same answer as plain text, replies indented, ready to paste into a prompt.
comments reddit, x, bluesky, youtube 0 to 20 replies to include. default 0.
depth reddit 0 to 10, how deep the reply tree goes. needs comments.
thread x, bluesky false stops at the linked post instead of adding the author's own thread. default true.
transcript youtube true or a language code like "en": the captions as timed lines in post.extra.transcript.

sources

any http link gets an answer. source in the answer names the reader that took it.

source links what you get
reddit posts and comment links the post, its score and subreddit, and the comment tree
twitter x and twitter posts the post, the post it quotes, the author's thread and replies
bluesky posts the post, the author's thread and replies
instagram posts and reels the caption, every photo or video, and its stats
threads posts the text, its media, likes, replies and reposts
tiktok videos and photo posts the caption, media, stats and the sound it uses
booru danbooru, e621, yande.re, konachan the image, its tags, rating and score
pinterest pins the title, text and the full-size image or video
list youtube playlists, soundcloud sets, spotify albums and playlists, apple music albums up to 100 entries in post.extra.entries, each with its link, title, artist and length
video youtube and the other video sites gronka downloads from the title, description, stats, tags and chapters; youtube also replies and transcripts
page any other web page the title, author, date, article text, picture and site name, from the page's own metadata

the answer

every source answers with the same shape.

field what it is
source the reader that answered, from the table above.
url the canonical link.
post the linked post.
thread the author's own posts around it, in order.
comments replies as a tree: each has depth and its own replies.
truncated true when there were more replies or entries than came back.

every post, and every reply, has these fields:

field what it is
author handle, name and url.
createdAt when it was posted, as an iso 8601 time.
title, text the words. a web page's text is its article.
media each with type (image, video or audio), url, alt, width and height.
links outbound links in the text, in order.
quoted, parent the post it quotes, and the one it replies to.
stats likes, reposts, replies, score and views. null when the source doesn't say.
flags nsfw, spoiler and edited.
extra what only that source has: chapters and transcripts for videos, entries for lists, the site name and description for pages. 
{
  "source": "list",
  "url": "https://open.spotify.com/album/...",
  "post": {
    "title": "Album name",
    "author": { "handle": null, "name": null, "url": null },
    "media": [
      { "type": "image", "url": "https://i.scdn.co/image/...", "alt": null, "width": null, "height": null }
    ],
    "extra": {
      "kind": "audio",
      "total": 12,
      "entries": [
        {
          "url": "https://open.spotify.com/track/...",
          "title": "First track",
          "artist": "Artist",
          "duration": 214
        }
      ]
    }
  },
  "thread": [],
  "comments": [],
  "truncated": false
}

errors

an error answers with {"error": {"code", "message"}}. the message is written to be shown to people as it is.

code http what happened
BAD_REQUEST 400 the body or an option is invalid.
BAD_URL 400 the url is missing, invalid, or not something that can be read.
UNSUPPORTED_SOURCE 400 that site isn't supported for this call.
VALIDATION_ERROR 400 the media or the request hit a limit.
UNAUTHORIZED 401 the api key is missing or not valid.
VERIFICATION_FAILED 403 the turnstile check failed.
CONTENT_GONE 404 the post is deleted, private or removed.
NOT_FOUND 404 no such route.
TOO_LARGE 413 the file is over the size cap.
NO_VIDEO 422 the post has no photo or video.
RATE_LIMITED 429 too many requests. retry after error.retryAfter seconds.
INTERNAL 500 something broke on our side.
NETWORK_ERROR 502 the source refused or couldn't be reached.
DOWNLOAD_FAILED 502 the download didn't finish.
CONTENT_FAILED 502 the content couldn't be read.

limits

50 downloads or content reads per 10 minutes, per ip, or per key when you send one. key checks are capped at 30 per 10 minutes per ip. a 429 carries error.retryAfter in seconds and the same value in a Retry-After header.

files gronka fetches itself (lane r2) have a 400 mb cap. on sites that list their file sizes, a video over it comes at a lower resolution that fits.

keys

POST /v1/keys, behind a turnstile check, returns a new key once. gronka keeps only a keyed hash of it, so a lost key can't be recovered, only replaced. DELETE /v1/keys with the key as its bearer token revokes it.

no request logs. files are gone after an hour. the full policy is on the privacy page.

reference

GET /v1/health is the service up
POST /v1/download get the files from a link
POST /v1/content read what a link says
POST /v1/keys create an api key
DELETE /v1/keys revoke an api key

the full schema is in openapi.json.
