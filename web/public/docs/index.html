paste a link, get the file.

public preview: the api runs at api.gronka.dev, but it may still change before the release.

auth

send your api key as Authorization: Bearer <key>. make keys on the account page.

download

send a link as json to POST /v1/download.

curl https://api.gronka.dev/v1/download \
  -H 'Authorization: Bearer <key>' \
  -H 'Content-Type: application/json' \
  -d '{"url":"https://x.com/user/status/123"}'

options: mode is auto (default), audio (an mp3) or mute (the video without its sound); start and end trim, in seconds or m:ss; split: false asks for one finished file instead of separate video and audio parts.

responses

direct

the link points to the file on its source site.

{
  "lane": "direct",
  "files": [
    {
      "url": "https://video.twimg.com/...",
      "filename": null,
      "type": "video"
    }
  ]
}

worker

signed links on dl.gronka.dev, good for an hour. usually one file, with kind video, audio or file (an image or other plain file). with merge: true, the files are separate video and audio streams for you to join, or send split: false to get one file. 

{
  "lane": "worker",
  "merge": true,
  "filename": "clip.mp4",
  "files": [
    {
      "url": "https://dl.gronka.dev/f/...",
      "filename": "clip.video.mp4",
      "kind": "video",
      "size": 30123456
    },
    {
      "url": "https://dl.gronka.dev/f/...",
      "filename": "clip.audio.m4a",
      "kind": "audio",
      "size": 1234567
    }
  ]
}

r2

a copy on cdn.gronka.dev, deleted after an hour.

error

a download error has an error.code and error.message.

{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "video duration exceeds the maximum allowed (60 minutes)."
  }
}

padded json

while a download runs, the response starts with spaces, then json. parse the full response as usual. errors after it starts use the json body; errors before it starts use an http status.

errors

common error codes. message is safe to show to users.

  • BAD_REQUESTthe request body or options are invalid.
  • BAD_URLthe url is missing or invalid.
  • DOWNLOAD_FAILEDthe download did not finish.
  • FORBIDDENthe request origin is not allowed.
  • INTERNALsomething broke on the server.
  • KEY_LIMITthe account already has 10 keys.
  • NETWORK_ERRORthe source refused or could not be reached.
  • NOT_FOUNDthe account, key or passkey was not found.
  • PASSKEY_INVALIDthe passkey could not be checked.
  • PASSKEY_LIMITthe account already has 10 passkeys.
  • RATE_LIMITEDtoo many downloads or one is already running. retry after retryAfter seconds.
  • UNAUTHORIZEDthe account or api key is missing or invalid.
  • TOTP_INVALIDthe 2fa or recovery code is wrong.
  • TOTP_LOCKEDtoo many wrong codes; wait, or use a passkey.
  • TOTP_OFF2fa is not on for this account.
  • TOTP_ON2fa is already on.
  • TOTP_REQUIREDthis account needs a 2fa code.
  • VALIDATION_ERRORthe media or request hit a limit.
  • VERIFICATION_FAILEDthe turnstile check failed.

accounts

an account is a number that holds api keys. add a passkey or 2fa to help protect it:

  • passkey: log in with your phone or laptop, no number needed. we only keep its public key.
  • 2fa: an authenticator app code on top of the number. turning it on gives 10 recovery codes, each works once, in the same totp field as a code.

wrong codes lock 2fa for 15 minutes after every 5, and for good after 100 in a row. a passkey login clears the lock.

with 2fa on, four actions also need a current code (or a recovery code) as code in the json body: POST /v1/account/rotate, DELETE /v1/account, POST /v1/passkeys/register/options and DELETE /v1/passkeys/{id}. a new number also signs out every other session.

limits

50 downloads per 10 minutes per ip, or per account with api keys (all keys share the account limit). api key checks are capped at 30 per 10 minutes per ip. files fetched by gronka (lane r2) have a 400 mb cap; images have a 50 mb cap. a 429 or 503 includes error.retryAfter in seconds and the same value in a Retry-After header.

privacy

no request logs. files are gone after an hour.

reference

  • GET/v1/healthcheck service status
  • POST/v1/downloadget files from a link
  • POST/v1/accountcreate an account
  • GET/v1/accountget account, keys and passkeys
  • DELETE/v1/accountdelete the account
  • POST/v1/account/rotatereplace account number
  • POST/v1/sessionstart a session
  • DELETE/v1/sessionend a session
  • POST/v1/keyscreate an api key
  • DELETE/v1/keys/{id}revoke an api key
  • POST/v1/totp/setupstart turning on 2fa
  • POST/v1/totp/enableturn on 2fa, get recovery codes
  • DELETE/v1/totpturn off 2fa
  • POST/v1/totp/recoveryreplace recovery codes
  • POST/v1/passkeys/register/optionsstart adding a passkey
  • POST/v1/passkeys/registerfinish adding a passkey
  • POST/v1/passkeys/login/optionsstart a passkey login
  • POST/v1/passkeys/loginlog in with a passkey
  • DELETE/v1/passkeys/{id}remove a passkey
